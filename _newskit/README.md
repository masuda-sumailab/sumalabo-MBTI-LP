# 賃貸物件ニュース 毎朝の係の手順書

このフォルダ(`_newskit`)は、サイトには出ません(`.vercelignore`)。毎朝の係(Claude)が使う道具と記録の置き場です。

- `ledger.json` … 切り抜き帳。短信1本=1件。ページはすべてここから作る
- `build.py` … 切り抜き帳から `news/` のページとサイトマップを作る道具
- `shell.html` … ページの外枠(見た目)。ふだんは触らない
- 猫の絵は `news/img/`

サイト: https://sumalabo-mbti-lp.vercel.app/news/ (運営: 住まらぼ 大阪福島店/AS-PARTNERS株式会社、担当: 増田さん)

## 絶対の決まり

1. **本番(`main`)に直接入れない。** 必ず別の枝に入れて、下書き(プルリクエスト)を出す。公開するのは増田さんがOK(Merge)を押したときだけ。
2. **よその記事を写さない。** 見出しも本文も写さない。使うのは、役所や会社が発表した資料の「事実と数字」だけ。自分の言葉で書き、出どころを必ず載せる。
3. **数字は発表資料そのもので2回確かめる。** 1回目で拾い、2回目は「この数字がそのとおり書いてあるか」を資料に当てて確かめる。資料を開けなかった数字、記憶にある数字は使わない。
4. **体験談を作らない。** 増田さんが言っていない「店頭の声」「お客様の話」を書かない。使ってよいのは `settings.osaka_facts` にあるものだけ。
5. **触ってよいのは `_newskit/ledger.json`・`news/`・`sitemap.xml` だけ。** ほかのページや設定は変えない。
6. 記事の中で「都心」は使わない(「市内」「大阪市内」と書く)。そのほかの使わない言葉は `settings.banned`。`build.py` が見つけて止める。

## 毎朝の手順

### 1. 置き場の最新を取り、OK待ちの下書きがあるか見る

```
git fetch --depth=50 origin main
gh pr list --state open --json number,headRefName,url,title
```

- 枝の名前が `news/` で始まる下書きが残っている → **新しい下書きは作らない。** その枝に切り替えて(`git fetch origin 枝名 && git switch 枝名`)、今日の分をそこに積む。
- 残っていない → `git switch -c news/今日の日付 origin/main`(例 `news/2026-11-16`)。

### 2. 調べる

- 調べ先は `ledger.json` の `watch`(テーマごと)と `upcoming`(日付が決まっている発表)。
- 対象は、**切り抜き帳のいちばん新しい号の翌日から今朝までに発表されたもの。** すでに切り抜き帳にある発表は載せない。発表から7日を過ぎたものは載せない。
- 今日が `upcoming` の日付なら、その発表が出ているかを発表元のページで確かめる(国の統計は朝8時半に出る)。出ていなければ今日は載せず、`upcoming` に残す。
- 新聞・テレビ・業界紙のサイトは「何か発表があったか」に気づくためと、あとで書く「全国ニュースになったか」の確認にだけ使う。短信の材料にはしない。

### 3. 選ぶ(1日0〜3本)

載せるもの:
- 大阪で部屋を借りる人・借りている人(とくに一人暮らし)の「お金・契約・住む場所」に関係がある
- 役所・会社・団体の発表資料が開ける
- 数字か、日付のはっきりした変更がある

載せないもの:
- 大家さん・投資家・不動産会社向けの話
- 会社の自社サービスの宣伝が中心の発表
- 個別の事件・事故
- 賛否が分かれる政治の論評
- 東京だけの話で、「大阪ではどうなる?」が書けないもの

**載せるものがない日は、何も作らない。** 下書きも出さず、「今日はありませんでした」と報告して終わる。同じテーマは1日1本まで。

### 4. 書く(切り抜き帳に1件足す)

`ledger.json` の `items` に足す。形は下の「1件の形」。

- `issue` と `posted` は今日の日付。`released` は発表があった日。
- `title` は自分の言葉で、数字を1つ入れる(70字まで)。`short` は45字まで。
- `lead` は2〜3文。だれが・いつ・何を発表したか、いちばん大事な数字。
- `facts` は2〜5個。ラベルと中身。数字は資料のとおり。
- `what` は言葉の説明や補足。専門用語は言いかえる(例: 募集家賃=不動産会社がサイトに載せている家賃)。
- `osaka`(大阪で部屋を借りる人には)は1〜3段落。大阪の数字は `settings.osaka_facts` と、過去の号に出どころつきで載せたものだけ。「当店の見方」は1つまでにして、言い切らない(「〜とは言えません」「〜と見ています」)。法律の判断や個別の助言は書かず、特集へ案内する。
- `cat` は所長(ねこ)のしめのひとこと。40字前後。「〜ですよ!」「〜ます!」の口調。
- `sources` は発表資料そのもののページ。`kind` は「役所の発表/会社の発表/団体の発表/報道」。報道しか出どころがないときは、媒体名を本文に書き、数字は最小限にする。
- `ukezara`(つなぐ特集)は1〜3本。`articles/` に実在するもの。テーマごとの候補は `themes` の `ukezara`。
- `words` は、このニュースで検索が増えそうな言葉を2〜5個。
- `zenkoku` は `{"status":"未確認","by":[],"checked":""}` で始める。
- 文は「です・ます」。短く。太字は `**…**`、特集へのリンクは `[[記事のslug|文字]]`、ほかの号へは `[[news:2026-11-05|文字]]`。

あわせて:
- `upcoming` の手入れ。過ぎた予定を消し、次の日付が発表元で確かめられたら足す。
- 過去7日の号の `zenkoku` を1回ずつ調べ直す。全国ニュース(NHK・全国紙・日経・関西のテレビ局・Yahoo!ニュースの主要欄)が同じ話題を取り上げていたら `{"status":"あり","by":["媒体名"],"checked":"今日"}`、なければ `"なし"`。これは記録だけで、ページは変わらない。今日の号がない日は、この更新のためだけに下書きを出さない。

### 5. 組み立てて確かめる

```
python3 _newskit/build.py --check
python3 _newskit/build.py
git status --short
```

- `×` が出たら直してやり直す。
- 変わってよいのは `_newskit/ledger.json`・`news/*.html`・`sitemap.xml` だけ。ほかが変わっていたら元に戻す。
- できた `news/今日.html` を読み返す。数字・日付・出どころのリンク・「大阪で部屋を借りる人には」が事実と意見に分かれているか。

### 6. 下書きを出す

```
git add _newskit/ledger.json news sitemap.xml
git commit -m "賃貸物件ニュース 11月16日号の下書き"
git -c push.negotiate=true push -u origin 枝名
gh pr create --base main --head 枝名 --title "…" --body "…"   # すでに下書きがあるときは gh pr edit で本文を直す
```

下書き(プルリクエスト)の題と本文は、増田さんが読む。むずかしい言葉を使わない。

- 題: `賃貸物件ニュース 11月16日(月)号の下書き:短い見出し`
- 本文に書くこと: 今日の短信(見出し・ひとことの中身・出どころ)/OKの押し方(このページの下の緑のボタン「Merge pull request」→「Confirm merge」)/直したいとき・載せたくないときは、Claudeのチャットで伝えてもらえば直す、または下書きを閉じる

出したあと1〜2分待って `gh pr view 番号 --json comments` を見る。Vercel が「プレビュー」のリンクを書き込んでいたら、それを報告に入れる(公開前の実際の見た目が見られる)。

### 7. 増田さんへの報告(最後のメッセージ)

短く、ふつうの言葉で。

```
今日の賃貸物件ニュースの下書きができました(2本)。
1. 見出し — 出どころ(発表元・日付)
2. 見出し — 出どころ
見る: プレビューのリンク(なければ下書きのリンク)
公開する: 下書きのページの緑のボタン「Merge pull request」→「Confirm merge」
直したい・載せたくないとき: チャットで教えてください
```

載せるものがなかった日: `今日は載せる発表がありませんでした。下書きは作っていません。` と、調べた先を1行。

うまくいかなかったとき(置き場に入れられない、道具が止まる、資料が開けない)は、何が起きたかをそのまま報告して終わる。別のやり方で無理に公開しない。

## 1件の形

```json
{
 "id": "20261116-01",
 "issue": "2026-11-16",
 "released": "2026-11-13",
 "posted": "2026-11-16",
 "theme": "yachin",
 "title": "見出し(自分の言葉・数字を1つ・70字まで)",
 "short": "短い見出し(45字まで)",
 "lead": "だれが、いつ、何を発表したか。**いちばん大事な数字**。",
 "facts": [["ラベル", "中身(数字は資料のとおり)"], ["ラベル", "中身"]],
 "what": ["言葉の説明や補足の段落"],
 "osaka": ["**大阪では…。**大阪の数字(出どころのあるもの)。", "**当店の見方:**言い切らない意見を1つ。"],
 "cat": "所長のひとこと。〜ですよ!",
 "sources": [{"org": "発表元", "doc": "資料の名前", "date": "2026-11-13", "url": "https://…", "kind": "会社の発表"}],
 "ukezara": [["osaka-yachin-souba", "カードに出す一言"]],
 "words": ["検索が増えそうな言葉", "…"],
 "zenkoku": {"status": "未確認", "by": [], "checked": ""}
}
```

公開したあとに誤りを直すとき: 本文を直し、`"modified": "直した日"` を足し、`what` の最後に「(11月20日訂正:どこをどう直したか)」と書く。

## テーマ

`themes` にある9つ。`label`(名前)・`desc`(入る話題)・`cat`(猫の絵の番号)・`ukezara`(つなぐ特集の候補)。テーマを足すときは、`news/img/neko-テーマ名.png` も要る。

## テーマのページと年表(2019年からの動き)

- `news/theme-テーマ名.html` は、そのテーマの短信を新しい順に並べたページ。一覧ページの「テーマごとの最新」から入る。`build.py` が作る。
- 年表は `ledger.json` の `history`。1件の形:

```json
{"theme": "yachin", "date": "2023-10", "added": "2026-11-14",
 "text": "**いちばん大事な数字。**何がどう変わったかを1〜3文で。",
 "sources": [{"org": "発表元", "doc": "資料の名前", "url": "https://…"}]}
```

- `date` は出来事の時期(`2019` / `2019-03` / `2019-03-05`)。`added` は年表に足した日。
- 年表は「当時の発表資料をさかのぼって調べ、あとからまとめたもの」と明記して出す。過去の日付で短信を出していたようには見せない(`items` に過去の日付の号を作らない)。
- 数字の確かめ方は短信と同じ(発表資料そのもので2回)。確かめられない出来事は入れない。
- 年表は、そのテーマに3件以上そろってからページに出る(それまでは切り抜き帳に貯めておくだけ)。
